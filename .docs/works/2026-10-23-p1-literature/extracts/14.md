Says:
When models are trained on data from the future, offline tests look better than they really are. The paper shows this with four common recommenders on four datasets. The cause is that the train/test split does not follow the global timeline. Models then recommend items that did not exist yet at the test time. Leakage also changes the accuracy numbers, and it changes the ranking of the models in unpredictable ways. The authors propose a timeline scheme as a fix.

Answers:

Q1. Data-leakage cases described (the paper names no leakage cases beyond the ones below):
- Section 2.2, leave-one-out split (leave-last-one-out) with collaborative filtering: the model learns that user A is similar to user C, and C's items are "future" for A's test point. Quote: "Next, we explain why data leakage occurs for this split strategy, because of collaborative filtering." (Section 2.2, page 7)
- Section 2.2, random split (random-split-by-ratio and random-split-by-user, see Table 2, page 4): these do not observe local or global timeline, so they leak for the same reason. Quote: "Hence random split leads to data leakage for the same reason as leave-one-out-split." (Section 2.2, page 8)
- Section 1, general case: training includes interactions after the test instances. Quote: "The training set may contain interactions that happen after the test instances in the test set." (Section 1, page 3)
- Symptom, future items in top-20 lists: models recommend items released after the test time. Quote: "Models evaluated in our experiments do recommend future items, which are only available in the system after the time point of a test instance." (Section 4.1, page 12)
- Duplicated interactions: the paper removes duplicates as preprocessing ("remove duplicated data", Section 3.1, page 10). It is not described as leakage. Quote: "and remove duplicated data". 
- Validation/test mixing: Section 3.2 tunes hyperparameters on "the second last interactions of the testing users". The paper does not call this leakage. Quote: "The hyperparameters of each model are tuned on the validation set which consists of the second last interactions of the testing users". (Section 3.2, page 11). Author should judge this one.
- Item/user features computed with future data: not found (see below).

Q2. The paper says split-by-timepoint is the only Table 2 split without leakage, but it proposes the timeline scheme as the better method. Quote: "We consider a timeline scheme to be a more reasonable scheme for fair offline evaluation of recommender models." (Section 5, page 20). The scheme also allows leave-one-out and random sampling of test points along the timeline: "The sampling of test instances can be by random or even by leave-one-out" (Section 5, page 20). Leave-last-out alone is not the recommendation.

Q3. The effect is large and not predictable. Quote: "Specifically, the magnitudes in Table 5 can be as high as 89.5%, and there is no particular pattern." (Section 4.2, page 17). Ranking changes are shown in Table 6 (page 18), with swaps of model positions across datasets.

Q4. Datasets: MovieLens-25M, Yelp, Amazon-music, Amazon-electronic. Quote: "We use MovieLens-25M, Yelp, Amazon-music, and Amazon-electronic datasets in our experiments." (Section 3.1, page 10). Models: BPR, NeuMF, SASRec, LightGCN. Quote: "The experiments are conducted with four widely used baseline models - BPR, NeuMF, SASRec, and LightGCN" (abstract, page 1). Metrics: HR@20 and NDCG@20 with non-sampled metrics (Section 3.3, page 11).
